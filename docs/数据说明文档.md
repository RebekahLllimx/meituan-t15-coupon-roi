## 3. 数据处理流程

### 3.1 场景约束构建

系统定义了下午茶场景的约束条件：

| 约束项 | 取值 | 说明 |
|--------|------|------|
| 场景名称 | afternoon_tea | 下午茶场景 |
| 时间范围 | 14:00-17:00 | 下午2点到5点 |
| 时间槽 | ["14:00", "14:30", "15:00", "15:30", "16:00", "16:30"] | 30分钟为一个时间槽 |
| BU关键词 | ['饮品', '甜点', '水果', '酒水茶饮'] | 包含这些关键词的业务单元 |
| POI关键词 | ['饮品', '奶茶', '咖啡', '生日蛋糕', '西式点心', '果切店', '整果店', '酒水店'] | 包含这些关键词的商户 |
| 排除BU关键词 | ['美食', '餐饮', '超市便利', '休闲食品', '食材'] | 排除这些关键词的业务单元 |
| 排除POI关键词 | ['快餐简餐', '中式正餐', '小吃', '小吃快餐', '火锅', '川菜', '粤菜', '烤串烤肉', '特色菜', '全球美食', '大型超市/卖场', '小型超市', '便利店', '零食店', '菜市场'] | 排除这些关键词的商户 |
| 行为关键词 | ['奶茶', '咖啡', '酸奶', '果汁', '甜品', '甜点', '蛋糕', '饮品', '水果', '茉酸奶', '生日蛋糕', '果切', '面包', '冰淇淋'] | 包含这些关键词的行为 |

### 3.2 场景订单提取

从原始订单数据中提取符合下午茶场景的订单：

1. **时间过滤**：下单时间在14:00-17:00之间
2. **业务过滤**：BU或POI分类包含场景关键词
3. **排除过滤**：排除不符合场景的BU或POI分类
4. **金额过滤**：订单金额在5-120元之间

### 3.3 漏斗结构提取

从用户行为序列中提取漏斗结构：

1. **行为时间解析**：将行为时间戳解析为标准时间格式
2. **行为阶段标准化**：将不同行为类型映射到标准阶段（view/click/cart/purchase）
3. **场景相关过滤**：只保留与下午茶场景相关的行为
4. **时间过滤**：只保留14:00-16:59之间的行为
5. **会话分析**：按用户和会话分组，计算各阶段转化率

### 3.4 特征分布拟合

对场景数据进行分布拟合，用于生成半合成用户：

| 特征 | 分布类型 | 描述 |
|------|----------|------|
| 价值 (V) | 对数正态分布 | 基于订单金额拟合 |
| 活跃度 (A) | 伽马分布 | 基于用户订单频次拟合 |
| 敏感度 (S) | 贝塔分布 | 基于用户优惠券使用率拟合 |

### 3.5 时间分布构建

构建不同时间槽的订单分布权重，用于模拟不同时间的订单密度。

### 3.6 优惠券目录构建

基于场景订单中的优惠券使用情况，构建优惠券目录：

1. **优惠券类型**：免费/付费
2. **膨胀类型**：膨胀/非膨胀
3. **优惠券价值**：3元/5元/8元等
4. **客单价提升**：基于优惠券使用前后的订单金额差异

## 4. 半合成用户生成

### 4.1 生成流程

1. **用户画像采样**：从原始用户画像中采样
2. **参数生成**：基于分布模型生成价值(V)、活跃度(A)、敏感度(S)参数
3. **参数调整**：根据用户画像特征（如会员等级、生命周期阶段）调整参数
4. **贝叶斯更新**：为每个用户生成后验敏感度分布参数

| 数据文件 | 必需字段 | 完整性评估 |

| 用户画像表 | user_id, 会员状态, 历史实付分层 | 完整 |

### 5.2 数据一致性

- **用户ID一致性**：三个数据集的用户ID格式一致
- **时间格式一致性**：下单时间和行为时间戳格式统一
- **业务分类一致性**：BU和POI分类标准统一

### 5.3 数据有效性

- **订单金额**：过滤掉异常值，保留5-120元的订单
- **时间范围**：只保留下午茶时段的订单和行为
- **业务相关性**：只保留与下午茶场景相关的订单和行为

## 6. 数据使用注意事项

1. **数据隐私**：所有用户数据均为脱敏处理后的样本数据
2. **数据代表性**：样本数据代表了下午茶场景的用户行为特征
3. **数据局限性**：
   - 仅包含下午茶场景的数据
   - 可能存在样本偏差
   - 时间范围有限
4. **数据更新**：如需更新数据，应保持相同的数据结构和字段含义
