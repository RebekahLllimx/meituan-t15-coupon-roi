下午茶半合成仿真与策略优化系统说明

一、方法论重构说明

本项目已经从“直接用小样本数据估计用户真实转化率”的旧路径，切换为“数据约束 + 分布拟合 + 半合成仿真 + 因果校正 + Contextual Bandit 优化”的新路径。

当前统一的方法论是：

1. 承认原始数据无法形成真实用户闭环。
2. 不再尝试把行为表、订单表、画像表强行打通成监督学习样本。
3. 用订单数据拟合用户异质性分布，用行为序列提取 Funnel 结构，用画像做解释与生成约束。
4. 在仿真环境中计算不同补贴策略的反事实效果。
5. 在预算约束下用 Contextual Bandit 进行探索与分配。

一句话总结：

不是“用数据直接训练结果”，而是“用数据定义结构，在结构中推导结果”。

二、数据的角色重新定义

1. 用户画像表

字段：
- user_id
- 常驻城市
- 年龄
- 用户生命周期阶段
- 会员状态
- 历史实付分层（365天）

用途：
- 提供用户分层解释
- 为半合成用户生成提供静态画像约束

不再用于：
- 直接预测下单
- 与行为表做强匹配建模

2. 神券订单数据样例

用途：
- 定义下午茶场景过滤规则
- 拟合用户价值分布 V
- 拟合用户活跃度分布 A
- 拟合价格敏感度分布 S
- 提取时间场景修正
- 提取候选券和客单 uplift

3. 用户行为序列

用途：
- 仅作为结构性先验
- 提取 Funnel：
  - view → click
  - click → cart
  - cart → purchase

不再用于：
- 估计真实 beta
- KNN 扩展到画像用户
- 拟合真实用户的个体参数

三、当前系统的正式流程

订单数据 -> 场景过滤 -> 分布拟合（V, A, S）
行为序列 -> Funnel 结构（p1, p2, p3）
画像表 -> 用户生成约束
-> 生成虚拟用户池
-> Funnel 仿真
-> 券作用到 p3
-> 因果校正
-> Bandit 策略优化
-> 敏感性分析

四、场景定义

当前聚焦“下午茶场景”，采用以下约束：

1. 时间约束
- 14:00-17:00

2. 订单业态约束
- 保留：饮品、甜点、水果、酒水茶饮
- 排除：正餐、快餐、超市、零食、泛餐饮

3. POI约束
- 保留：咖啡、奶茶、果切店、整果店、生日蛋糕、西式点心、酒水店
- 排除：快餐简餐、中式正餐、小吃、火锅、川菜、粤菜、大型超市等

4. 金额约束
- 仅保留较符合下午茶消费场景的订单金额区间

五、分布拟合

1. 用户价值 V

从下午茶场景订单金额拟合：

log(order_value) 近似服从正态
因此：
V ~ LogNormal(mu, sigma)

2. 用户活跃度 A

从场景内用户订单数拟合：

A ~ Gamma(shape, scale)

3. 用户价格敏感度 S

从场景内用户用券率拟合：

S ~ Beta(alpha, beta)

六、Funnel 建模

行为序列仅用于构建漏斗结构，不用于估计个体转化率。

定义：
- p1: view -> click
- p2: click -> cart
- p3: cart -> purchase

系统将其作为全局结构性先验，再将用户异质性嵌入其中。

七、用户异质性嵌入

对每个生成用户，定义状态：
- V：用户价值
- A：活跃度
- S：价格敏感度

三段转化函数：

p1 = sigmoid(f(V, time))
p2 = sigmoid(f(A))
p3 = sigmoid(f(S, V))

自然转化率定义为：

beta = p1 * p2 * p3

八、优惠券作用机制

券不再整体抬高转化率，而只作用于最后一层 purchase 阶段。

券增量函数：

delta = S * log(1 + coupon / V) * (1 - p3)

有券时：

p3_coupon = p3 + delta

因此：

P(order | no coupon) = p1 * p2 * p3
P(order | coupon) = p1 * p2 * p3_coupon

九、GTV 与因果校正

1. GTV

无券期望：
GTV0 = P0 * V

有券期望：
GTV1 = P1 * (V + uplift)

2. 成本

Cost = P1 * coupon_value

3. 因果增量

当前正式目标为：

Delta_GTV_causal = (GTV1 - GTV0) * (1 - beta)

解释：
- beta高的用户本来就容易下单
- 对这类用户发券时，真实增量应被折减

十、优化器

当前优化器不是静态排序，而是 Contextual Bandit + 预算约束。

1. 状态
- state = (V, A, S)

2. 动作
- action = coupon

3. 奖励
- reward = Delta_GTV_causal

4. 不确定性

uncertainty = 1 / sqrt(1 + exposure)

5. UCB价值

value_ucb = value + alpha * uncertainty

6. 约束
- 每用户最多一张券
- 总预算约束
- 单券型覆盖上限

十一、贝叶斯更新

当前系统已将价格敏感度参数分布化：

S_i ~ Beta(alpha_i, beta_i)

在 Bandit 多轮训练中：
- exposure 增加
- success / failure 累积
- 后验参数更新

因此仿真环境不是静态的，而是“策略反馈后继续更新”的。

十二、敏感性分析

当前系统会扫描若干场景扰动，例如：
- 用户价值提升
- 券响应增强
- 更保守的 Funnel 场景

输出：
- ROI 变化
- 因果增量 GTV 变化
- 覆盖用户规模变化

十三、已经删除的旧逻辑

以下方案已明确删除，不应再出现在报告与答辩表述中：

- LLM 生成 beta
- 行为序列 KNN 扩展
- delta = coupon_rate - beta
- 用极小样本直接拟合真实个体转化率
- 单点转化模型 P = beta + delta

十四、当前方案与《ChatGPT-数据扩充方法推荐 copy》的一致性

已经实现的关键推荐项包括：

1. 承认数据断裂，转向仿真主线
2. 用订单数据定义用户分布
3. 用行为序列定义 Funnel 结构
4. 生成虚拟用户池
5. 在仿真环境中比较不同券策略
6. 加入因果校正
7. 引入 Bandit 探索机制
8. 加入贝叶斯后验更新
9. 做敏感性分析

尚未实现、但可作为后续扩展的内容包括：

1. 外部天气/节假日场景变量
2. 更细粒度的 Markov 状态转移
3. 更完整的 Bayesian Bandit
4. 与外部 POI 数据联动的品类增强

十五、报告中建议使用的统一表述

建议使用以下标准句式：

“本文将原始小样本数据视为结构约束而非完整训练样本：基于订单数据拟合用户价值、活跃度与价格敏感度分布，基于行为序列提取下午茶购买 Funnel 结构，基于画像表引入静态异质性约束，在此基础上构建半合成仿真环境，并通过因果校正和 Contextual Bandit 完成预算约束下的发券策略优化。”
